# 千问办公接入智谱DeepSeek：办公Agent打响模型聚合战

> 原文链接：[https://www.laoshoucun.com/qianwendt/2441](https://www.laoshoucun.com/qianwendt/2441)

<p>8 月 14 日晚上，我打开<a href="https://www.laoshoucun.com/qianwen" target="_blank" rel="noopener">千问办公</a>首页，前沿模型那个档位里多出两个名字，GLM-5.3 和 DeepSeek V4 Pro，加上之前就有的 Qwen3.8-Max，阿里、智谱和 DeepSeek 三家模型算是凑齐了，同一页面上头一回见到三家厂子的名字并排摆着。挺意外。</p>
<p><img decoding="async" src="https://cdn.laoshoucun.com/web/2026/08/20260816220939_793405.png" alt="千问办公模型聚合"></p>
<p>DeepSeek V4 Pro 的上下文窗口有 100 万 Token，一次最多能输出 384K，长程任务和 Agent 任务串联是它的强项。GLM-5.3 侧重点在编程和复杂工程任务，选谁取决于手里是什么活。</p>
<p>我头一个念头是，为什么千问办公不只用自家模型，后来想想也合理。一个复杂的 Agent 任务要连续跑好几个步骤，代码和推理这些环节好说，长文本和响应速度也各有所长，单靠一个模型很难处处最优。超长文档分析得靠 DeepSeek 的 100 万上下文，复杂编程 GLM-5.3 更顺手，多模态和中文场景 Qwen3.8-Max 还是首选，聚合起来等于工具箱里多备了几把。</p>
<p>现在的用法还是用户自己选模型，复杂方案和自动化工作流走前沿模型，快速调研、表格分析这些轻活走经济模型，成本低一档。更进一步的方向是路由，让 Agent 在后台自己调度，简单任务交给便宜快的，复杂推理交给能力强的，用户不用懂每个模型的长短板。</p>
<p>千问办公不是头一家这么干，腾讯 WorkBuddy、字节 TraeWork 和百度库库AI 早就有类似布局，几家大厂站到了同一条战线上。这场竞争还在早期，什么时候切模型、按单次请求还是一整段任务来调度，行业都还没统一答案。我的看法是，模型聚合对用户是实打实的好事，不用在多个工具之间来回倒腾，一个平台就能挑到各家最好的能力，下一步就看谁家的路由做得聪明了。</p>
